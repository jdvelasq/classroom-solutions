La verificación automática puede reutilizar la misma sesión de Nox que se ejecuta localmente. Así, GitHub y el computador del estudiante comprueban el producto de la misma manera.

1. Desde la raíz de este PRE, copie el repositorio local que terminó en PRE-17 y abra una rama:

   cp -R ../PRE_17_github_actions/temp/github_actions_case temp/github_actions_nox_case
   cd temp/github_actions_nox_case
   git switch -c add-nox-check

   En `cp -R`, `-R` copia una carpeta y todo su contenido. En `git switch -c add-nox-check`, `-c` crea la rama add-nox-check y cambia inmediatamente a ella.

2. Reemplace la verificación de PRE-17 por una sesión de Nox:

   cp ../../data/repository_template/noxfile.py .
   cp ../../data/repository_template/src/main.py src/
   cp ../../data/repository_template/tests/test_report.py tests/
   cp ../../data/repository_template/.github/workflows/tests.yml .github/workflows/
   git rm .github/workflows/quality.yml tests/test_environment_report.py

   `noxfile.py` declara la sesión `tests`, que instala `requirements.txt` y ejecuta `tests/test_report.py`. `tests.yml` le indica a GitHub que instale Nox y ejecute esa sesión en cada push y en cada pull request. `git rm` retira del repositorio el flujo y la prueba de PRE-17, que esta sesión reemplaza.

3. Compruebe localmente la misma sesión que ejecutará GitHub:

   python3 -m pip install nox
   python3 -m nox -s tests

   `-m` ejecuta pip y Nox con el mismo Python. `-s tests` selecciona la sesión llamada `tests` en `noxfile.py`.

4. Confirme y publique la rama:

   git add noxfile.py src tests .github
   git commit -m "ci: run nox tests"
   git push -u origin add-nox-check

   En `git commit -m`, `-m` indica que el texto siguiente es el mensaje del commit. En `git push -u origin add-nox-check`, `-u` asocia la rama local con la remota para futuros push y pull.

5. En el repositorio personal de GitHub, abra Compare & pull request:

   a. Verifique que la rama base sea main y la de comparación sea add-nox-check.
   b. Cree el pull request con el título: ci: run nox tests.
   c. Espere a que aparezca el resultado verde de `Nox tests` en la sección de checks.
   d. Solo cuando el check esté en verde, haga Merge pull request y confirme la fusión.

6. Actualice la rama local y vuelva a la raíz de este PRE:

   git switch main
   git pull --ff-only
   git log --oneline -2
   cd ../..

   En `git pull --ff-only`, `--ff-only` acepta la actualización solo si Git puede avanzar main sin crear una fusión local adicional.

Para terminar, desde la raíz de este PRE guarde la evidencia de su historial:

   git -C temp/github_actions_nox_case log --oneline -2 > submission/git_log.txt

   `git -C temp/github_actions_nox_case` ejecuta Git dentro del repositorio de práctica sin cambiar de carpeta. El símbolo `>` guarda la salida del comando en `submission/git_log.txt`.
